Phase 0 • Start Immediately

Rapid Start with General-Purpose Hardware

No custom PCB is required to begin. Use readily available ESP32 development boards and general-purpose modules immediately, while observing which connections students repeatedly make. Those observations become the evidence for the V1 Companion Board.

Build now • Learn now • Observe now

The off-the-shelf setup is not a throwaway prototype. It becomes the first teaching platform and the validation instrument for the custom board.

Design Value • Safety • Form Factor

What the Platform Must Save, Improve and Protect

The objective is not simply fewer wires. V1 should reduce repetitive setup time, reduce connection errors, improve low-voltage safety and make experiments more repeatable, while preserving deliberate hands-on circuit learning.

Less setupTarget: materially reduce repeated wiring before each experiment.
Fewer errorsKeyed, labelled connections reduce polarity and pin-mapping mistakes.
More lab timeStudents spend more time measuring, coding and analysing instead of rebuilding routine wiring.
ReusableOne compact companion platform can support many experiments and batches.

Faculty / Lab Saving Model

Do not claim a fixed saving until Phase 0 measurements are available. Instead, the proposal should track the following measurable quantities:

Recommended claim: “Savings will be demonstrated from Phase 0 data rather than assumed.” This makes the proposal credible and allows the college to calculate annual savings across batches.

Accuracy principle
Standardized ports improve repeatability of the connection and power arrangement. They do not make the sensor or measurement itself automatically accurate. Calibration, sensor tolerance, ADC resolution, grounding and measurement technique remain part of the student's learning.
Safety by architecture
V1 should remain a low-voltage educational platform. Use protected 5 V / 3.3 V rails, current limiting or resettable protection where appropriate, reverse-polarity protection, clear power indication and physically distinct power connectors. Mains experiments should remain external to the V1 board and use appropriately rated, enclosed laboratory equipment. The platform should not imply that connectorization makes hazardous voltages safe.

01 | Core Idea

Not another ESP32 breakout board

The platform should sit between a trainer kit and a professional prototyping bench: students learn the circuit, but do not spend most of the laboratory period fighting with duplicated VCC/GND/signal jumper wiring.

01

Universal carrier

ESP32 socket, protected GPIO, ADC, DAC, I²C, SPI, UART, PWM, level shifting, power rails and test points.

02

Functional modules

Sensors, relays, motors, displays, RFID, RS485, CAN, LoRa and other modules connect through standardized interfaces.

03

Engineering lab

Students can move from GPIO and IoT to power conversion, signal conditioning, current/voltage measurement and industrial communication.

Design principle
Make routine connections standardized, while deliberately leaving selected test points, headers and a small prototyping area so students can still learn real wiring, debugging and circuit construction.
01A | V1 Design Decision

Start small. Solve the wiring problem first.

The first product should not be a large trainer. It should be a compact ESP32 Universal Companion Board whose primary job is to make routine student experiments plug-and-play. Everything else is added only when the curriculum needs it.

V1 = Minimal Viable Platform
01

ESP32 stays familiar

Use the replaceable 38-pin ESP32 DevKit. Students still see, program and debug the actual controller.

02

6 × 3-pin GPIO/IO ports, 2 × I²C ports and 2 × servo ports replace repetitive VCC/GND/signal wiring.

03

Small prototyping zone

Keep a compact breadboard/header area so jumper wires remain available where learning the circuit is the objective.

04

Add modules later

Power, actuator, instrumentation and industrial modules are separate purchases, not forced into V1.

01B | Build Guide

Building V1 on a general-purpose PCB

No custom fabrication needed to start. A good-quality double-sided, plated-through-hole prototype board gives a durable, reusable V1 companion board immediately, while the custom PCB spec is still being validated by Phase 0 data.

01

Board selection

Double-sided PTH protoboard, gold/tin-plated pads, 0.1" pitch, ~100×70mm. Avoid single-sided phenolic; pads lift under repeated student soldering.

02

Zone the layout

Mirror the V1 envelope: power/protection, ESP32 socket, I²C ports, GPIO ports, servo ports, and a bare prototyping strip.

03

Bus wiring

Solder solid-core power/GND bus strips along two edges once. Every port then taps the nearest bus point instead of a wire back to the ESP32.

04

Label & test

Label every port on top (no silkscreen on protoboard). Verify each port with a multimeter before student use.

Error-reduction rules on protoboard

  • ✓ Polarized/keyed connectors (JST-XH) so modules can't insert backwards
  • ✓ Fixed color per signal type across every port: red = power, black = GND, yellow = I²C, blue = servo
  • ✓ Series resistor (220-330Ω) on GPIO signal lines to connectors
  • ✓ PTC fuse + reverse-polarity diode on power input
  • ✓ Decoupling caps near ESP32 power pins
  • ✓ One labelled test point per rail and bus

Build & test sequence

  • 1. Solder power/GND bus strips first, verify continuity
  • 2. Mount ESP32 female headers, confirm no shorts to bus
  • 3. Add I²C, GPIO and servo connectors one zone at a time
  • 4. Test each port with a multimeter and one known-good sensor before moving to the next
  • 5. Label ports, then run a full experiment end-to-end
  • 6. Hand to 2-3 students for a trial session before replicating

06 | Wiring Philosophy

Minimize wires, don't eliminate learning

Use the interactive comparison below.

Wires should normally NOT be needed for

  • ✓ BME280 / DHT / PIR / basic I²C sensors
  • ✓ OLED / RTC / I²C ADC/DAC modules
  • ✓ SG90/MG90S servo ports
  • ✓ onboard relay channels
  • ✓ onboard buttons, LEDs, buzzer and potentiometer
  • ✓ standard RS485/CAN expansion modules

Wires SHOULD still be available for

  • • breadboard and free-form circuit experiments
  • • oscilloscope / logic-analyzer probing and test leads
  • • external DC motors, pumps, solenoids and custom loads
  • • custom transistor/MOSFET/op-amp circuits
  • • external 4–20 mA loops and industrial sensors
  • • non-standard third-party modules and student-designed circuits

08 | Recommended Development Roadmap

Build it in the right order

PHASE 01

Freeze interfaces

Choose ESP32 form factor, connector family, pin map, power rails and module mechanical standard.

PHASE 02

Prototype carrier

Build ESP32 + I/O + power + measurement first. Validate protection and connector ergonomics before adding everything.

PHASE 03

Module ecosystem

Create 10–20 standardized sensor/actuator modules with identical labeling, pin conventions and documentation.

PHASE 04

Curriculum + scale

Map modules to experiments, lab sheets, firmware examples and bulk procurement. Then optimize the BOM for 50/100/250 kits.

Final recommendation

Do not make a giant single PCB containing every sensor. Make a durable universal carrier and a standardized family of inexpensive plug-in modules. Integrate the high-value infrastructure: power, protection, measurement, connectors, actuator drivers and test points. Keep the replaceable ESP32 and most sensors/actuators modular.

Procurement Note

Existing products are references, not the final answer

The market already proves demand for plug-and-play ESP32 trainers and broad IoT experiment boards. The opportunity is to combine that usability with an E&C-oriented power and instrumentation layer, while keeping the platform affordable enough for institutional deployment.
